## 今後やること

### 1. データの追加

新規店舗を Airtable に追加していく。追加時に埋めるべきフィールド。

| フィールド | 必須度 | 備考 |
|---|---|---|
| 店名 | 必須 | |
| 住所 | 必須 | 「新潟県」から始める形式で統一 |
| エリア | 必須 | 住所の市区町村と一致させる |
| 営業時間 | 必須 | 定休日も同じ欄に。シーンタグ判定に使う |
| 説明文 | 必須 | **定型文を書かない**（下記参照） |
| 既存タグ | 必須 | スラッシュ区切り。既存表記に合わせる |
| メニュー | 推奨 | ランチあり判定に使う |
| 一言 | 推奨 | 20字以内。ルールは下記 |
| 座標 | 推奨 | |
| 写真 | 推奨 | |

**説明文で書いてはいけない型**

- 「〇〇は新潟市の△△です」（地域＋業態だけの文）
- 「ドライブや散策の際のご立ち寄りにもおすすめです」
- 「朝からの営業で、朝食やモーニングセットをお楽しみいただけます」
- 「新潟県内でおすすめのスポットとしてご紹介させていただきます」
- その他、他店にも当てはまる汎用文

→ 店固有の情報だけを書く。書けないなら短くていい。

**一言のルール**

- 20字以内
- 評価語を使わない（旨い / 絶品 / 逸品 / 人気 / おすすめ / 美味しい）
- 「です」「ます」で終わらない
- 地域名＋業態だけの汎用文にしない
- 語尾は分散させる（〜が名物 / 〜が自慢 / 体言止め）
- 書けない場合は空にする。無理に埋めない

### 2. 写真の追加

- 撮影候補リスト: `logs/photo_plan.md`（43件、中央区に29件集中）
- 撮ったら Airtable の写真フィールドに追加
- 併せて「一言」も自分の言葉で埋められる（訪問すれば書ける）
- 写真が溜まったら、スライド1枚目の濃茶背景を写真に差し替える

**撮影時のメモ**

- 外観・店内・一品の3枚あれば投稿に使える
- スマホで十分
- 定休日は火曜が最多（6件）、金土は0件

### 3. 投稿の改善サイクル

Instagram のインサイトを見て、次の投稿に反映する。

**見る指標**

| 指標 | 意味 | 改善対象 |
|---|---|---|
| リーチ | 何人に届いたか | 1枚目のフック文・見た目 |
| 視聴維持率 | どこで離脱したか | スライドの構成・秒数 |
| 保存数 | 後で見返したいか | CTA・内容の実用性 |
| プロフィールアクセス | サイトに行きたいか | CTAの文言 |

**見方の目安**

- **1〜2秒で離脱が多い** → 1枚目が弱い。フック文か、背景（写真化）を変える
- **中盤で離脱** → 店舗ページが単調。一言の質か、3秒という表示時間を疑う
- **最後まで見られているのに保存されない** → CTAの訴求が弱い
- **保存されるのにサイトに来ない** → プロフィールのリンク導線

**シーン別の比較**

投稿履歴は `data/posted_scenes.json` に残っている。シーンごとのリーチを比較すると、どの切り口が刺さるか分かる。

- 状況系（日曜営業・テイクアウト可など）
- 名物系（かき氷・プリンなど）

数本たまったら、伸びたシーンを増やし、伸びないシーンは外す。

## 運用上の注意

今日の作業で判明したこと。CLAUDE.md にも記載済み。

- **Airtable の処理は毎回最新リストをAPI取得する**。過去のログのレコード一覧を流用しない（削除済みレコード混入を3回起こした）
- **完了報告の前に結果を自分で確認する**。未確認なら「未確認」と書く
- **期待値と結果が一致しない場合、原因を特定するまで次に進まない**
- 監査スクリプト自体にバグがありうる。件数が不自然なときは監査側を疑う
