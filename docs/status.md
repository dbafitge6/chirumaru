## 📝 データ追加時のルール

### 説明文（Airtable 「説明」フィールド）

**禁止される定型文（自動除去対象）**:
```
カテゴリーの説明
- 〇〇の名物です
- 〇〇が特徴です
- △△で有名です
- ◇◇が好評です
- 季節限定□□を提供
- △△はフードコーディネーターが
```

**記載方法**:
- 実際の店舗オリジナルの説明のみ
- テンプレ文は AI 生成・手動除去対象

### 一言メモ（Airtable 「一言」フィールド）

**必須ルール**:
- ✅ **20字以内**（日本語は1字 = 1文字）
- ✅ **評価語禁止**: 「美味しい」「素晴らしい」「最高」「完璧」など
- ✅ **です/ます禁止**: 「〜です」「〜ます」で終わらない
- ✅ **句点禁止**: 「。」を付けない

**良い例**:
- 「スキー場帰りに立ち寄れる」
- 「国道8号線沿いの喫茶・カフェ」
- 「旬の新潟食材を主役にしたコース」

**悪い例**:
- ❌ 「ここのスイーツは本当に美味しいです。」（21字、評価語、です、句点）
- ❌ 「新潟最高峡をめぐるドライブコース上の隠れ家的カフェ。」（26字、句点）

## ⚠️ 運用上の注意

### 【重要】Airtable API 取得時のルール
- **毎回最新リストを API 取得する**
  - ❌ 過去のログ・スクリーンショットのレコード一覧を流用しない
  - ✅ 削除済みレコード混入防止、常に最新状態を保証
  - コード: `scripts/auto_instagram_post.py:495-550` の Airtable fetch セクション

### 【重要】完了報告のルール
- 完了報告の前に**結果を自分で確認する**
  - ❌ 「完璧」「完了」「正常に動作」といった語を使わない
  - ✅ 事実だけを書く（「取得 12 件」など）
  - ✅ 期待値と結果が一致しない場合、原因を特定するまで次に進まない

### 【重要】エラーハンドリング
- **期待値と結果が一致しなければ、調査・修正まで続行する**
  - 例：Instagram Reach 134 ≠ GA4 Sessions 136 → 原因確認（異なるデータソース）
  - 例：一言 56 件未記入 → 手動確認・修正（データ品質向上）
